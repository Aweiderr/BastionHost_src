## 1. 总判断

四份文档的分层是对的：规划讲怎么建，需求讲验收，详细设计引用需求号，库表单独成册。初始化、三权分立、SSH 命令管控、审计防篡改已经写到可评审的深度。

当前不能按现稿冻结基线，更不能直接按现稿开工。主要风险不是「写得不够多」，而是：

1. 章节编号和交叉引用已经错位
2. 角色模型和容量指标四处不一致
3. P0 范围过宽，把尚未验证的能力与市场标配捆在一起
4. 设备自身运维能力写得散、写得浅：网络配置、恢复出厂、备份还原、密钥备份、SNMP、日志服务器都没有按可运营功能单列

建议：**先统稿，再砍首版范围，把设备运维管理补成独立功能，再补契约（接口 / 测试 / 部署）。**

### 2.5 技术口径要写准

1. **SSH 密钥**  
   规划写「托管公钥」，需求 FR-04-13 同时要求托管公钥与私钥。应拆成两条能力：
   - 资产侧：公钥分发、指纹核验、轮换、吊销、后门密钥检测
   - 堡垒机侧：私钥代签，私钥不出安全边界、不下发客户端

2. **国密 TLS**  
   文中写「国密 TLS 1.3（GM/T 0024）」。GM/T 0024 对应传统国密套件，和 TLS 1.3 国密不是同一件事。密评材料应按实际采用的协议栈写，不要混称。

3. **CentOS 7**  
   已停止维护。信创清单保留麒麟 / UOS / openEuler；Ubuntu 22.04 LTS 作为通用兼容；CentOS 7 降为「不承诺」或删除。

4. **工控协议**  
   规划表 12-2 已标 P2，总体架构却写成「支持」。对外口径以协议矩阵为准：未做的协议写「不支持」，不要写「支持」。

## 3. 产品功能建议（成熟、可落地）

原则：只建议市场上已验证、用现有开源或成熟组件能做出来的能力。不建议把「架构上能画出来」的能力写进首版 P0。

参考的成熟路径（不绑定具体品牌，只说明可行性）：

- 无 Agent 协议代理（SSH / SFTP / RDP）是国内堡垒机的主流形态
- Web 终端（xterm.js）+ 图形网关（Guacamole 一类）已大规模使用
- 字符录像用 typescript / asciinema 一类流式记录，图形录像用录像文件 + 对象存储
- 命令控制先做「行级 + 正则」，不要承诺完整 Bash AST
- 身份源先做本地账号 + LDAP / AD + TOTP，OIDC / SAML 放到随后一版
- 密码卡 / 密码机作为密评部署选项，软件国密模块用于研发与 POC，不要把硬件密码卡写成所有环境的前置条件

### 3.1 建议的版本切分

| 版本 | 定位 | 验收口径（建议） |
|---|---|---|
| V1.0 可交付 | 能管 Linux / Windows 日常运维，能过等保审计项 | 500 资产、100 并发、双机、SSH/SFTP/RDP、命令黑名单、录像回放、三员 |
| V1.1 | 把数据库和改密补齐 | Web SQL（MySQL / PostgreSQL）、口令轮换、日志外发、批量命令 |
| V1.2 | 密评与多租户 | 密码机对接、证书体系、租户隔离、达梦 / 金仓、国产 OS 认证 |
| 后续 | 差异化 | 应用发布、Oracle 协议、云资产同步、行为分析、工控 |

#### D. 运维会话（产品核心）

| 功能 | 建议 | 落地要点 | 与现稿关系 |
|---|---|---|---|
| Web SSH | 做 | xterm.js；窗口自适应、中文、复制粘贴策略、多标签 | 保留 FR-04-01；Web 优先，桌面客户端后移 |
| Web SFTP | 做 | 在线文件树、上传下载、进度、文件摘要 | 保留；FTP 降为 P2（明文协议，新项目尽量不推） |
| Web RDP | 做 | 图形网关；常见分辨率、输入法、录像 | 保留 FR-04-02；多显示器、本地盘映射不要进 P0 |
| VNC / Telnet | 可做可后移 | Telnet 对网络设备仍有需求，建议 P1；VNC 可 P1 | 现稿 P0 过满 |
| 会话监控与强拆 | 做 | 在线会话列表、只读旁观可后置，管理员强制断开必须有 | 现稿「共享 / 接管」过重；**强拆应升为 P0** |
| 断线重连 | 做 | 代理侧会话保留短时（如 60 秒）供重连 | 保留；「节点故障会话迁移」降级，实现成本高且不稳定 |
| 进入运维 ≤ 3 步 | 做 | 资产列表 → 连接 → （可选）选账号 | 保留体验要求 |

**明确不要在 V1.0 承诺的会话能力：**

- 剪贴板四种模式 + 本地盘映射：Web 端做不完整，原生客户端才像样。V1.0 只做「允许 / 禁止粘贴」到终端。
- 会话在代理节点之间热迁移：工程难度高，失败体验差。改成「该节点不再接新会话，存量自然结束或用户重连」。
- 按键级完整还原 vi / top：字符流录像可以回放，但「按命令跳转」对全屏程序不可靠。V1.0 做到字符流回放即可，命令索引只对「完整行命令」生效。

这是相对竞品的卖点，建议做，但把「识别能力」写成可验收的边界，不要写成万能解析器。

| 功能 | 建议 | 可验收边界 | 不可承诺 |
|---|---|---|---|
| 危险命令黑名单 | 做 | 内置模板：`rm -rf /`、`mkfs`、`dd of=/dev/`、`shutdown` 等；动作：放行 / 告警 / 阻断 | — |
| 正则规则 | 做 | 按用户组 + 资产组生效；命中规则编号写入审计 | — |
| 命令白名单 | 做 | 只对高敏资产启用，默认不打开 | 不要默认全网白名单，运维会废掉 |
| 二次确认 | V1.1 或受限 P0 | 首版可做成「本会话弹确认」；跨人审批确认要推送通道，容易拖垮体验 | 5 分钟内找主管在线确认，首版很难稳定 |
| 组合绕过 | 部分做 | 拦截 `;` `&&` `\|\|` 管道、简单的 `$( )` 与反引号 | 不承诺所有 shell 方言、不承诺二进制、不承诺 `eval` 全覆盖 |
| 提权审计 | 做 | 识别 `sudo` / `su` / `doas` 起始行，后续命令带上目标账号标签 | 不承诺 sudoers 所有别名展开 |
| 端口转发默认禁止 | 做 | `-L -R -D`、X11、Agent 转发默认关，按策略开 | 这是安全底线，应保留 P0 |
| SFTP 方向与大小限制 | 做 | 上传 / 下载 / 双向 / 禁止；单文件大小、扩展名 | MIME 深度检测、病毒扫描放到 V1.1 |
| 规则测试器 | 做 | 输入一条命令，显示命中哪条规则、什么动作 | **建议新增**，没有它策略无法实施 |

### 3.3 建议补齐但现稿偏弱的功能

这些是成熟产品实施时几乎必问、现稿写得不够或没有单列的能力。

1. **资产 / 账号 / 用户 Excel 导入导出**  
   没有导入，500 资产以上的项目实施会拖死。应作为 V1.0 P0。

2. **在线会话监控与强制断开**  
   审计员和值班人员的刚需。共享操作、接管可以后置，强拆不能后置。

3. **命令规则测试器**  
   安全管理员配完规则必须能自测，否则不是可运营功能。

4. **直连告警的可运营做法**  
   「禁止直连」不能只写在需求里。V1.0 给两种落地手段即可：
   - 资产侧 sshd / RDP 只放行堡垒机网段（实施手册写清楚）
   - 可选：周期性核对资产登录来源，发现非代理 IP 告警（不必首版做全流量探测）

5. **磁盘水位保护**  
   录像盘到阈值（如 85%）停止新建会话、告警、不删未归档数据。这是生产上真实会炸的点，现稿容量写了很多，保护策略不够硬。

6. **内置命令策略模板**  
   按 Linux、网络设备、数据库给三套默认模板。不要让客户从空白正则开始。

7. **工单与紧急放行的闭环**  
   日常：工单 → 授权 → 运维 → 到期回收。  
   值班：紧急放行 → 强告警 → 24 小时内补单。  
   缺任一端，现场都走不通。

8. **软件国密 + 密码卡双模式**  
   研发、POC、中小客户用软件模块；等保三级 / 密评项目插密码卡或接密码机。初始化需求里「检测不到密码卡则阻止初始化」会把产品卖不出去，应改为：
   - 密评模式：无密码卡不可完成初始化
   - 标准模式：允许软件模块，界面和审计明确标记「未使用认证密码模块」

9. **设备运维管理（网络 / 出厂 / 备份 / 密钥 / 日志 / SNMP）**  
   现稿把这些能力拆在初始化、系统参数、数据需求、接口清单里，实施和售后无法按页面交付。应按 3.9 节升为独立功能，而不是继续挂在「系统参数配置」下面。

### 3.6 命令管控的可落地方案

不要按「完整 shell 解析器」设计，按两层做：

1. **行级策略（V1.0）**  
   - 以回车提交的一行作为判定单位  
   - 支持关键字、正则、内置危险模板  
   - 对 `;` `&&` `||` 做拆分后再逐段匹配  
   - 命中阻断则不把该行转发到资产，并在终端回显原因

2. **流级记录（V1.0）**  
   - 原始 PTY 字节流全程录像，保证 `vi` / 密码输入也能回放  
   - 口令输入做回显抑制与落库脱敏（`passwd` 后续输入不进命令明细）

3. **增强解析（V1.1）**  
   - 有限支持 `$( )`、反引号、续行 `\`  
   - 提供「规则测试器」和误报反馈  
   - 明确文档：不保证 `zsh` / `fish` / 编码混淆 / 二进制逃逸 100% 拦截  
   - 高敏资产用白名单，而不是把黑名单做到完美

这和现稿 FR-04-19 / FR-04-21 的差距要在需求里写清楚，否则测试无法通过。

### 3.8 建议的首版用户故事（用来代替 100 条 P0）

先用 1–12 条卡住业务闭环，再用 13–17 条卡住设备运维。需求条目为这些故事服务，而不是反过来。

1. 实施人员在本地完成初始化，创建三员，超管可封存。
2. 系统管理员从 Excel 导入资产和账号，连通性检测为失败资产告警。
3. 安全管理员给「运维一组」授权 Linux 生产组的 `ops` 账号，仅工作日、仅办公网。
4. 运维人员 Web 登录（口令 + TOTP），三步进入 SSH，口令或密钥由系统代填。
5. 运维人员执行 `rm -rf /data` 被阻断，终端看到原因，审计员能搜到该命令。
6. 运维人员 SFTP 上传文件，超大小被拒；允许的文件有名称、大小、摘要记录。
7. 运维人员打开 Windows 资产的 RDP，全程录像，事后可回放。
8. 厂商人员提交工单，审批通过后 4 小时内可登录指定主机，到期自动失效。
9. 夜间故障走紧急放行，安全管理员事后能看到告警和补单状态。
10. 审计管理员按人 / 资产 / 时间找回放，导出取证包，导出本身有日志。
11. 审计管理员强制拆掉一个违规会话。
12. 任一节点宕机，新会话可在另一节点建立；数据库可从备份恢复。
13. 系统管理员修改设备管理 IP / DNS / NTP 后仍能登录；配错时可从 console 改回。
14. 系统管理员定时备份配置与数据库，并在备机或本机还原到可登录状态。
15. 使用密码卡时，安全管理员完成主密钥分片备份；换卡后双人复核还原，业务可继续。
16. 审计日志可送到指定日志服务器；服务器不可达时本地缓存并告警，恢复后补发。
17. 双人复核执行恢复出厂后，再次访问进入初始化向导，原业务数据与密钥不可恢复。

做到前 12 条，业务闭环能卖。13–17 条是一体机 / 等保交付的设备运维闭环，缺了会在实施和售后反复被问。功能细节见 3.9。

## 3.9 设备运维管理：现稿缺什么、建议怎么写

这是一体机和等保交付的标配能力，和「运维别人的资产」不是同一类功能。现稿多数只在初始化或数据需求里带过一句，没有独立页面、独立验收、独立权限。

### 3.9.1 对照结论

| 能力 | 现稿有没有 | 现稿写到哪 | 缺口 | 建议优先级 |
|---|---|---|---|---|
| 设备自身网络配置 | 只有初始化 | IR-04：初始化时配管理地址、网关、DNS、NTP；验收写「可修改且留痕」 | 初始化之后没有系统管理页；未写主机名、多网口（管理口 / 业务口）、静态路由、HA VIP、配错回滚、console 兜底 | **V1.0 P0** |
| 恢复出厂设置 | 有一条，位置不对 | IR-30，**P1**，挂在「初始化安全要求」下 | 未定义保留项 / 清除项、入口（Web + console）、双人复核、与系统还原的区别、完成后必须进入初始化向导 | **V1.0 P0**（从 P1 上调） |
| 系统备份和还原 | 有名，不够用 | FR-07-09 P0；数据需求 7.3 给了 RPO/RTO | 未区分配置备份 / 库备份 / 录像备份；未写备份目标（本地、NFS、SFTP）；未写还原后是否仍已初始化；未写不能用系统备份代替密钥备份 | **V1.0 P0**（细化，不新造编号也可） |
| 密钥备份和还原 | 只有初始化分片 | IR-13 主密钥分片；FR-09-04 生命周期；DR 写「密码机内备份 + 分片托管」 | 没有换卡、双机同步、定期校验、分片导入导出的运营流程；和系统备份混在一起会出事 | **V1.0 P0**（密评模式必做；标准模式写「软件模块备份」） |
| SNMP 管理 | **没有** | 四份文档均未出现 SNMP | 网管监控一体机的常规入口缺失 | **V1.0 P1**（一体机商用建议首发就有） |
| 日志与日志服务器 | 有外发接口，没有管理功能 | FR-07-06 是管理操作日志；FR-08-07 / IF-05 是 Syslog 外发，**P1** | 没有运行日志查询、级别、轮转、磁盘配额；没有日志服务器地址 / 协议 / 设施 / 测试发送 / 断线缓存的配置页 | **本地日志 V1.0 P0；外发 V1.0 P0 或 P1** |

一句话：**备份、出厂、密钥在需求里「被提到了」，但不能按现稿做成产品；网络配置和 SNMP 基本缺；日志管理被写成了「记日志」而不是「管日志」。**

### 3.9.2 设备网络配置（建议新增 FR-07-11）

初始化里的 IR-04 只解决「第一次能上网」。上线后改 IP、换网段、加业务口是日常操作，必须单独做。

**范围（V1.0）：**

| 项 | 说明 |
|---|---|
| 主机名 | 修改后同步到界面、日志、SNMP sysName |
| 管理口 | 静态 IPv4、掩码、网关；可选 DHCP（仅 POC，生产默认静态） |
| 业务 / 代理口 | 与管理口分离；代理流量走业务口，管理 Web / SSH 走管理口 |
| DNS | 至少 2 个 |
| NTP | 至少 2 个；偏移超过 1 秒告警（审计时间依赖） |
| 静态路由 | 可选，跨网段回源用 |
| HA VIP | 双机时配置；与管理口同网段 |
| 生效策略 | 保存后倒计时确认（如 60 秒），超时自动回滚到旧配置，避免改错 IP 后锁死 |
| 兜底 | console / 串口始终可改网络，不依赖当前管理 IP |

**不要写进 V1.0：** 完整防火墙策略编辑器、IPv6 双栈（可预留字段）、动态路由协议。开放端口用「服务开关」（Web、SSH 管理、Syslog、SNMP）即可。

**权限：** 仅系统管理员。变更记管理日志，含前后值。

### 3.9.3 恢复出厂设置（建议 IR-30 升 P0，或单列 FR-07-12）

用户要的行为是对的：**清库清配置，下次访问回到初始化向导。** 这和「从备份还原」不是同一件事，文档必须拆开。

| | 恢复出厂 | 系统还原 |
|---|---|---|
| 目的 | 设备转售、重交付、彻底作废当前租户 | 误操作或故障后回到某个已运行时点 |
| 结果 | 未初始化状态，打开就是初始化页 | 仍是已初始化，账号和策略还在（来自备份） |
| 密钥 | 密码卡主密钥销毁或归零，分片作废 | 不自动销毁密钥；密钥按 3.9.5 单独处理 |
| 审批 | 双人复核（系统管理员发起 + 安全或审计确认） | 系统管理员；跨机还原可加复核 |

**清除：** 业务库、审计库、对象存储中的会话数据、本地用户与策略、初始化标志、软件密钥材料、密码卡业务密钥。

**建议保留：** 设备序列号、固件、许可文件（可选勾选）、管理口 IP（可选勾选，避免重置后找不到设备）。这两项必须在确认页明文列出。

**入口：** Web 管理页 + console。Web 不可用时必须能在串口完成。执行前二次输入当前管理员口令，展示不可逆警告。完成后强制重启，未初始化前不开放业务端口（与 IR-29 一致）。

**审计：** 恢复出厂会清日志，因此必须在执行前把「即将出厂重置」事件外发到日志服务器（若已配置），并写到不可被业务库删除的设备本地安全区（即使只有一条）。否则无法证明做过重置。

### 3.9.4 系统备份和还原（细化 FR-07-09）

现稿验收只有「手动与定时、加密、恢复前提示、可中止」，实施时一定会被问备份了什么、备份到哪、还原后能不能开机。

建议拆成三种备份，界面上分开展示：

| 类型 | 内容 | 默认策略 | V1.0 |
|---|---|---|---|
| 配置备份 | 网络、用户、资产、账号密文引用、授权、策略、系统参数、许可 | 每日 + 变更后；体积小 | 必做 |
| 系统备份 | 配置备份 + 数据库（不含录像文件） | 每日全量，可加增量 | 必做 |
| 录像备份 | 对象存储复制 / 另存 | 跟存储复制，不塞进系统备份包 | 可与存储方案一起做，不要和配置备份绑死 |

**备份目标（V1.0 至少两种）：** 本机磁盘（配额告警）+ SFTP/NFS 远端。USB 作为一体机可选项。

**约束：**

- 备份包加密；口令或密钥不进包明文
- **备份包不含密码卡主密钥材料**，只含密钥索引与台账；主密钥走 3.9.5
- 还原前检查：版本是否匹配、磁盘是否够、是否有在线会话（先排空或强拆）
- 本机还原：还原后仍为已初始化，用备份时的三员账号登录
- 新机还原：允许，但许可需重新绑定；若原环境用密码卡，必须先做密钥还原再启业务
- 定时备份失败告警；支持下载、校验、删除旧备份

现稿 DR 表 7-3 的 RPO ≤ 1 分钟是数据库容灾指标，不要写进「配置备份」验收。配置备份验收写成：每日备份成功、抽一次还原能登录并看到资产即可。

### 3.9.5 密钥备份和还原（建议新增 FR-09-13，密评模式 P0）

IR-13 只覆盖初始化时生成主密钥并分片。运营中还有换卡、卡损坏、双机配对，必须单写。

**V1.0 流程：**

1. **备份：** 主密钥在卡内，导出 Shamir 分片（如 3 中取 2）；分片文件加密；由不同人保管；备份完成做一次「试还原到校验区」或至少校验分片完整性。
2. **定期：** 每季度校验分片仍可读；卡内密钥与台账一致。
3. **还原：** 新卡或空卡 → 双人输入分片 → 卡内恢复 MK → 与密钥台账核对 → 业务密钥可继续解包。失败则卡保持空，不覆盖。
4. **双机：** 备机配对走密钥同步，不靠拷贝系统备份包。
5. **与系统备份隔离：** 系统还原不会自动把主密钥还原进卡；顺序必须是「密钥还原 → 系统还原」或文档写死的相反顺序，并在界面强制检查卡状态。

**权限：** 安全管理员发起，审计管理员见证。系统管理员不能单独还原密钥。

**标准模式（无密码卡）：** 软件模块密钥用加密文件备份，保存在与系统备份分离的路径；同样双人；审计标记「软件密钥备份」。

### 3.9.6 SNMP 管理（建议新增 FR-07-13，P1）

四份文档都没有 SNMP。若以一体机卖给政府 / 运营商 / 大型企业网管，这是监控接入的常规方式，建议首个正式版本就做，但不阻塞 SSH 主路径。

**V1.0 范围：**

- 只做 **SNMPv3**（authPriv）；SNMPv2c 可关、默认关
- 只读社区 / 用户；不提供 SNMP 写配置（改 IP 仍走 Web / console）
- 标准 MIB：系统、接口、磁盘、CPU、内存
- 企业 MIB 最少字段：在线会话数、今日登录失败、HA 状态、许可剩余天数、服务存活
- Trap / Inform：磁盘超阈值、服务宕、HA 切换、许可到期、备份失败
- 配置：监听口、用户、认证/加密算法、Trap 目标地址；提供「测试 Trap」

**不要做：** SNMP 改配置、完整性能基线分析。那是网管软件的事。

### 3.9.7 日志和日志服务器管理（建议把 FR-07-06 拆开，并上调 FR-08-07）

现稿把三件不同的事混在一起：

| 类型 | 现稿 | 应做成 |
|---|---|---|
| 管理操作日志 | FR-07-06 | 保留；授权变更、备份、改 IP、恢复出厂、密钥操作 |
| 运维审计日志 | FR-05 | 保留；会话、命令、文件、录像索引 |
| 系统运行日志 | NFR-06-03 只有「完备」 | **缺管理页**：级别、检索、下载、轮转 |
| 日志服务器 | FR-08-07 / IF-05，P1 | **应有配置页**，等保经常要求日志进专用服务器 |

**V1.0 建议做成一个「日志管理」页：**

1. **本地运行日志：** 级别（ERROR/WARN/INFO）、按时间 / 模块 / 关键字检索、下载、保留天数、磁盘上限；超限告警，禁止把审计日志挤掉（审计与运行日志分盘或分目录）。
2. **日志服务器：** 地址、端口、UDP/TCP/TLS、RFC5424、设施、哪些类别外发（运行 / 管理 / 审计可分别勾选）、本机源地址、测试发送。
3. **可靠性：** 服务器不可达时本地队列缓存（容量可配），恢复后按序补发；队列满告警，审计日志优先于运行日志。
4. **安全：** 外发可签名（现稿已有方向）；审计日志外发通道与运行日志可分开。
5. **权限：** 系统管理员配服务器和运行日志；审计管理员看审计日志；谁都不能在界面上删除审计日志。

等保场景建议：**审计日志外发在 V1.0 就要能配**，不要留在 P1。运行日志外发可以同期做，成本几乎一样。
